# Bold — الخطة النهائية الموحدة

هذه الوثيقة هي المرجع الأساسي لخطة مشروع Bold من الآن، وتلغي أي تعارض بين الخطط القديمة.

## القرار المعماري النهائي

| الجزء | مسؤوليته |
|---|---|
| POS | البيع، المرتجعات، الوردية، العملاء أثناء البيع، الطباعة والمزامنة Offline |
| Warehouse App | كل إدخال المخزن: المنتجات، الموردون، المشتريات، التحويلات، الجرد والتسويات |
| Admin Web | العرض، المتابعة، التقارير، التدقيق وإدارة النظام؛ بدون إدخال تشغيلي للمخزن |
| Backend | مصدر الحقيقة وقواعد العمل والمخزون والفواتير والمزامنة |
| نظام الدفع | خارج Bold؛ نسجل الطريقة والمرجع فقط عند الحاجة |

### القواعد الثابتة

- الـPOS لا يدير المشتريات أو إدخال المخزون.
- Admin Web لا يُستخدم لإدخال العمليات اليومية.
- لا نكرر Business Logic داخل التطبيقات؛ كل القواعد في Backend.
- عملية البيع المكتملة محليًا لا تُرفض بسبب تغير سعر Cloud.
- الدفع خارج النظام ولا يعطل مزامنة الفاتورة.
- تغيير تصميم الفاتورة لا يغير بيانات البيع.
- نستمر كـModular Monolith ولا ننتقل إلى Microservices.

# P1 — تطبيق المخزن المستقل

هذه أعلى أولوية وظيفية بعد إغلاق P0.

## 1. حدود التطبيقات

### POS

يظل مسؤولًا فقط عن:

- البيع.
- المرتجعات للعملاء.
- فتح وإغلاق الوردية.
- الطباعة.
- العملاء المرتبطين بالبيع.
- Offline outbox والمزامنة.

### Warehouse App

يصبح مسؤول الإدخال التشغيلي الوحيد عن:

- المنتجات.
- المقاسات والألوان والباركود.
- الموردين.
- فواتير المشتريات.
- استلام البضاعة.
- مرتجعات الموردين.
- التحويلات بين الفروع.
- الشحن والاستلام.
- التالف والفاقد.
- الجرد.
- التسويات.
- طباعة Barcode labels.

### Admin Web

يصبح Read-only تشغيليًا:

- عرض المنتجات.
- عرض المخزون.
- عرض المشتريات.
- عرض الموردين.
- عرض التحويلات.
- عرض الفواتير.
- عرض التقارير.
- عرض التحذيرات والمطابقة.
- عرض سجل التدقيق.

وتظل إجراءات إدارة النظام فقط:

- المستخدمون والصلاحيات.
- الفروع.
- تسجيل وتعطيل الأجهزة.
- إعدادات النظام.

## 2. تسويات المخزون

- زيادة جرد.
- عجز جرد.
- تالف.
- فاقد.
- تصحيح إدخال.

- السبب.
- المستخدم.
- الفرع.
- الوقت.

## 3. توحيد Inventory Ledger

التأكد أن كل تغيير مخزون يأتي من حركة:

- Sale.
- Customer return.
- Purchase receipt.
- Supplier return.
- Transfer out.
- Transfer in.
- Damage/loss.
- Stock adjustment.

ممنوع مستقبلًا تحديث `InventoryStock` مباشرة بدون Ledger movement.

## 4. المطابقات

- [ ] رصيد المخزون مقابل Movement Ledger.
- [ ] البضاعة بالطريق مقابل Transfer Ledger.
- [ ] تكلفة المخزون مقابل Cost Ledger.
- [ ] الفواتير مقابل حركات البيع.
- [ ] الفواتير المتأخرة من أجهزة POS.
- [ ] Negative stock warnings.
- [ ] Sequence gaps.
- [ ] Price variance.

Admin Web يعرض النتائج فقط، والتصحيح يتم من Warehouse App أو Command متخصص.
